|===
| Requirement | Description

|[[REQ-FS,Functional Suitability]] **Functional Suitability**
|* The software manages the schema and data transformation of the specified database.

|[[REQ-CO,Compatibility]] **Compatibility**
|* The managed data **has to** integrate into spring-boot and run as init container within k8s.

|[[REQ-US,Usability]] **Usability**
|* The software **has to** read changelog files for liquibase in yaml or xml format.
* The software **should** be able to read the changelog files from ZIP files.

|[[REQ-RE,Reliability]] **Reliability**
|The systems needs to operate for world wide consumption.

|[[REQ-MT,Maintainability]] **Maintainability**
|The software should be easily maintainable.
This includes using widely used frameworks so help can be given quite easily.

|===

== Quality Scenarios

[cols="<.<1,<.<9a",options="header",frame="topbot",grid="rows"]
|===
| ID | Scenario


2+h| Functional Suitability

|[[FS01,Update Database Schema and Data (FS01)]] **FS01**
| The software must update the database schema and migrate data according to the changelog files (defined in Liquibase YAML or XML format).
This includes executing all necessary SQL statements in the correct order.

|[[FS02,Verify Database Schema (FS02)]] **FS02**
| The software must verify that the database schema has been correctly applied and matches the expected state after applying the changelog files.
This ensures data integrity and correct schema state.


2+h| Compatibility

|[[CO01,Run as init-container within k8s (CO01)]] **CO01**
| The software must be deployable as an init-container within a Kubernetes cluster and integrate with spring-boot applications.
It must complete its schema update before the main application container starts.


2+h| Usability

|[[US01,Liquibase changelog files (US01)]] **US01**
| The software **has to** read changelog files in Liquibase format (YAML or XML).
The changelog file path must be configurable via file parameter.

|[[US02,Liquibase changelog files as ZIP file (US02)]] **US02**
| The software **should** be able to read the changelog files from within ZIP files.
This provides flexibility in how changelog files can be packaged and distributed.

2+h| Reliability

|[[RE01,Working hours 24/7 (RE01)]] **RE01**
| The system needs to operate for world-wide consumption without scheduled maintenance windows.
Database updates must be reliable and not cause data loss or corruption.


2+h| Maintainability

|[[MT01,Small Team (MT01)]] **MT01**
| Maintaining the software must be possible for a small team with limited resources.
This requires using widely established frameworks and following best practices so help can be obtained easily.

|===
